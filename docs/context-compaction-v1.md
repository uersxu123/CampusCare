# 请求前上下文压缩

## 数据流

1. 工具返回后，RAG 仅去掉字段完全相同的重复条目，不截正文、不摘要。
2. 序列化结果不超过 8000 个估算 token，完整追加到工具消息；超过时先保存完整业务结果，再追加 `executionId` 引用。
3. `ContextBuilder` 只组装所选上下文。每次模型请求前，`ContextCompactor` 统一检查消息、调用参数、工具定义和输出 schema；`AiClient` 最后执行硬预算校验。
4. 达到 24000 时争取压到 20000：旧工具结果 → Skill 的明确示例/参考段 → 旧记忆。最后两轮工具调用批次及其所有结果不变。
5. 旧工具先落库，然后调用 LLM 输出结论、条件、例外、未知和原文摘录。摘要格式、摘录来源以及压缩收益验证成功后才替换消息正文；工具调用 ID 和配对不变。
6. Specialist 向下游交付最终可见证据视图，不重新展开已存储或摘要的完整原文。原文和摘要分别保存，摘要不能充当原文引句。

## 默认参数

| 参数 | 值 |
| --- | --- |
| 模型窗口 | 32768 |
| 触发 / 目标 | 24000 / 20000 |
| 硬输入上限 | min(28672, 窗口 - 本次输出 - 1024) |
| 大结果入库阈值 | 严格大于 8000 |
| 保留工具轮数 | 至少最近 2 个批次，不按单个工具计数 |
| 每个用户回合摘要调用总上限 | 3，嵌套执行预算共享计数 |
| 摘要输出 / 超时 | 1024 token / 10 秒 |
| 摘要最小剩余时间 | 大于超时 + 15 秒最终回答预留 |
| 回读每页预算 | 1536 token，包含为工具包装预留的空间 |
| 原文有效期 | 86400 秒 |
| Redis 缓存 TTL | 最多 3600 秒，不超过原文有效期 |

计量使用项目统一的中英文估算函数，并非模型 tokenizer 的精确值。生产应结合 provider 的 prompt token 统计校准。

## 保护与失败语义

- 最近两轮即使超过软目标也不截短；若再无可压缩部分，只要低于硬上限就允许继续，记录 `targetReached=false`。超过硬上限拒绝发送。
- 没有旧工具时直接检查 Skill，再检查记忆。现有 Skill 以规则为主，没有明确示例/参考段时该阶段跳过；权限、Workflow、输出契约不参与压缩。
- 记忆仅摘要旧 workingMemory 和 relevantHistory，保留最近两条 workingMemory、用户画像、原会话摘要和当前任务约束。
- 摘要超时、无效引句、空结果、变大、预算耗尽时保留原消息，不反复摘要同一输入；剩余阶段仍按预算尝试。
- 原文保存失败时不发布可回读引用；超大结果终止本次循环，返回 `TOOL_RESULT_STORE_FAILED`。
- “相同引句来自原文”可以用代码检查；摘要是否语义完整仍依赖模型，需要政策适用条件和否定/冲突场景评测，不能声称绝对无损。

## 原文与回读

`tool_execution_records` 保存完整业务结果。`wire_result_json` 和 `normalized_result_json` 当前保存相同的业务 data，不表示另行保存 MCP 传输信封；`raw_hash` 对这些业务数据计算。

`tool_result_views` 保存通过原文引句校验的工具摘要视图；`model_context_manifests` 保存触发值、前后估算、保护轮数和处理动作。Agent 诊断中也包含 `contextCompression`。

`read_tool_evidence(execution_id, evidence_ids=[], focus, cursor)` 从第一页开始读取所有证据。指定证据 ID 可缩小范围；用返回的 `nextCursor` 继续。父块和子块是不同 fieldPath，片段附带 offset。focus 当前仅表达读取意图，不执行语义检索。游标绑定原文 hash 和证据选择；每次读取仍校验用户、会话、有效期和原文 hash。回读不重复落库。

Redis 只是缓存；失效或故障回源 MySQL。数据库原文列使用 LONGTEXT，迁移为 `0017_tool_result_longtext`。已有库应按部署流程执行迁移；不要为了这项功能贸然执行涉及旧业务数据转换的其他迁移。

## 验证

自动测试覆盖最近批次保护、两轮以内不摘要、工具/Skill/记忆顺序、共享调用额度、失败回退、引用校验、分页重组、数据库/Redis 回源与跨用户拒绝。

本地真实 Qwen 合成数据测试记录在 `target/verification/context-compaction-v1/live-summary.json`；真实 MySQL/Redis 合成数据测试记录在同目录 `live-storage.json`。它们验证机制，不代表完整校园政策回答质量评测。
